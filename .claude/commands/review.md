# コードレビュー

現在のブランチの未コミット変更をレビューしてください。

## レビュー手順

1. `git status` と `git diff` で変更内容を確認
2. 変更されたファイルを読み込んで詳細を確認
3. 以下の観点でレビュー

## レビュー観点

### コード品質
- コードは明確で読みやすいか
- 適切な命名規則が使われているか
- 重複コードはないか
- SOLID原則に従っているか

### Rails ベストプラクティス
- Rails の規約に従っているか
- N+1 クエリの問題はないか
- 適切なバリデーションが設定されているか
- Strong Parameters が正しく使われているか

### テスト
- 新しい機能に対するテストがあるか
- テストは十分なケースをカバーしているか
- `described_class` を使用しているか（RSpec）

### セキュリティ
- SQL インジェクションの脆弱性はないか
- XSS の脆弱性はないか
- 認証・認可が適切に実装されているか
- 機密情報がハードコードされていないか

## 出力フォーマット

以下の形式でフィードバックを提供してください：

### 🔴 CRITICAL（重大な問題）
セキュリティ脆弱性、データ損失リスクなど

### 🟠 IMPORTANT（重要な問題）
パフォーマンス問題、N+1クエリ、ロジックエラーなど

### 🟡 SUGGESTION（提案）
スタイル改善、可読性向上など

### 🔵 QUESTION（質問）
設計意図の確認、明確化が必要な点など

### ✅ 良い点
コードの良い部分を具体的に挙げる

---

最後に、**承認可能か** または **修正が必要か** を明確に述べてください。
