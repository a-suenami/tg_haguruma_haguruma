# ファイルレビュー

指定されたファイル `$ARGUMENTS` をレビューしてください。

## レビュー手順

1. ファイルを読み込む
2. ファイルの責務と設計を理解する
3. 以下の観点でレビュー

## レビュー観点

### コード品質
- **単一責任の原則**: クラス/メソッドは一つの責務のみを持っているか
- **命名**: 変数、メソッド、クラス名は明確で意図が伝わるか
- **複雑度**: メソッドが長すぎないか、ネストが深すぎないか
- **DRY原則**: 重複コードはないか

### Ruby/Rails 固有
- **イディオム**: Ruby らしい書き方か
- **Rails規約**: Rails Way に従っているか
- **マジックナンバー**: 定数化すべき値はないか

### モデルの場合
- バリデーションは適切か
- アソシエーションは正しく定義されているか
- スコープは再利用可能か
- コールバックは適切に使われているか

### コントローラの場合
- アクションはシンプルか
- Strong Parameters は正しいか
- before_action は適切か
- Fat Controller になっていないか

### テストファイルの場合
- テストケースは十分か
- エッジケースをカバーしているか
- テストは独立しているか
- モックは適切に使われているか

## 出力フォーマット

```
## ファイル概要
- ファイルパス:
- 責務:
- 行数:

## 発見事項

### 🔴 CRITICAL
[重大な問題があれば記載]

### 🟠 IMPORTANT
[重要な問題があれば記載]

### 🟡 SUGGESTION
[改善提案があれば記載]

### ✅ 良い点
[コードの良い部分]

## 総合評価
[このファイルの全体的な評価とアクションアイテム]
```
