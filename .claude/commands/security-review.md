# セキュリティレビュー

現在のブランチの変更に対してセキュリティ観点でのレビューを実行してください。

## レビュー手順

1. `git diff` で変更内容を確認
2. 変更されたファイルを詳細に分析
3. 以下のセキュリティチェックリストに基づいてレビュー

## OWASP Top 10 チェックリスト

### A01: アクセス制御の不備
- [ ] 認証が必要なアクションに適切な before_action があるか
- [ ] 認可チェック（Pundit/CanCanCan等）が実装されているか
- [ ] 水平権限昇格の脆弱性はないか（他ユーザーのリソースへのアクセス）
- [ ] 垂直権限昇格の脆弱性はないか（管理者機能へのアクセス）

### A02: 暗号化の失敗
- [ ] パスワードは適切にハッシュ化されているか（bcrypt等）
- [ ] 機密データは暗号化されているか
- [ ] APIキーや秘密鍵がハードコードされていないか
- [ ] 本番環境の認証情報がコードに含まれていないか

### A03: インジェクション
- [ ] SQL インジェクションの脆弱性はないか
  - 生SQL使用時のパラメータバインディング
  - `where("column = '#{params[:value]}'")`のようなパターン
- [ ] コマンドインジェクションはないか
  - `system()`, `exec()`, バッククォート使用箇所
- [ ] LDAP/XPath インジェクションはないか

### A04: 安全でない設計
- [ ] ビジネスロジックに脆弱性はないか
- [ ] レースコンディションの可能性はないか
- [ ] 適切なレート制限があるか

### A05: セキュリティ設定ミス
- [ ] デバッグモードが本番で無効か
- [ ] 不要なエンドポイントが公開されていないか
- [ ] エラーメッセージが過剰な情報を漏らしていないか

### A06: 脆弱なコンポーネント
- [ ] 既知の脆弱性を持つ gem を使用していないか
- [ ] 依存関係は最新か

### A07: 認証の失敗
- [ ] セッション管理は適切か
- [ ] ブルートフォース対策はあるか
- [ ] パスワードポリシーは適切か

### A08: ソフトウェアとデータの整合性の障害
- [ ] 信頼できないソースからのデシリアライズはないか
- [ ] YAML.load の使用（YAML.safe_load を使うべき）

### A09: セキュリティログとモニタリングの不足
- [ ] セキュリティ関連のイベントがログに記録されているか
- [ ] ログに機密情報が含まれていないか

### A10: サーバーサイドリクエストフォージェリ (SSRF)
- [ ] ユーザー入力を使った外部URLへのリクエストはないか
- [ ] URL バリデーションは適切か

## Rails 固有のセキュリティチェック

### XSS (クロスサイトスクリプティング)
- [ ] `raw` や `html_safe` の使用箇所は安全か
- [ ] ユーザー入力が適切にエスケープされているか

### CSRF (クロスサイトリクエストフォージェリ)
- [ ] `protect_from_forgery` が有効か
- [ ] API エンドポイントで適切なトークン検証があるか

### Mass Assignment
- [ ] Strong Parameters が正しく設定されているか
- [ ] 管理者専用属性が permit されていないか

### ファイルアップロード
- [ ] ファイルタイプの検証があるか
- [ ] ファイルサイズ制限があるか
- [ ] 実行可能ファイルのアップロードを防いでいるか
